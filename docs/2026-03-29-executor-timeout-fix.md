## 问题背景
开发群的开发和架构师会话都超时了但没有触发调度，AI返回了wait，忽略了超时信息
误以为"architect已响应 = 问题就处理中"。

)

{
## 优化内容
| 修改项 | 说明 |
|------|------|
| **新增-最高优先级** 执行者会话超时检查 | ✅ 新增决策优先级, |
| **判断逻辑** | ✅ 区分"架构师" vs "执行者"
        - 架构师超时 → 轻微问题,可以等待
        - **执行者超时 → 严重阻塞， 必须通知
        - **通知内容**: 强调执行者超时

 | 会话超时阈值 | 30分钟 → **10分钟** |
| **超时判断逻辑** | ✅ 区分角色
   - **执行者角色**: fullstack-dev, backend-dev, frontend-dev,   - **架构师角色**: architect,   - **执行者超时10分钟** → 强制通知
   - **架构师超时10分钟** → 可等待
        | 通知内容** | ✅ 强调执行者超时状态
   - 通知历史** | 记录超时信息
   - **返回**: `notify` (而非 `wait`)

 | 问题解决通知 | ✅ 优先级保持最高
        - 当责任群已解决问题, 且请求群还在等待 → 通知请求群
        - **通知内容**: "问题已解决， 可以继续验收"
 | 会话超时检查 | ✅ 已集成
  - 在分析前检查agent会话状态
  - 将超时信息传递给Claude
  - Claude决策时, 会优先考虑超时信息
 | 通知历史 | ✅ 讣记准确
  - 声明会话超时作为最高优先级
 | 决策准确性 | ⬆ | 大幅提升
 |
```
